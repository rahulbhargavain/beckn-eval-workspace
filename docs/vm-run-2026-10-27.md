## Finding: pinned hashes depended on line endings
`scenario_hash` hashed fixture files as raw bytes. The pins were computed on a Windows checkout (CRLF); the bundle clone on Linux has LF, so every fixture-backed scenario (the `PNNEG-*` set for `bpp-core`) hashed differently. The mockup then failed the runner's own "differs from the pinned version" check and went INCOMPLETE. `ds-core` was unaffected because `DISC-001` has an inline body.

Fix (test-first): new tests `test_scenario_hash_ignores_line_endings_in_fixtures` and `test_scenario_hash_still_changes_when_fixture_content_changes`; `scenario_hash` now normalises CRLF to LF before hashing; `bpp-core.json` re-pinned (`ds-core.json` unchanged). Local result after the fix: conformance 103 passed, 1 skipped; mockup 79 passed, 9 xfailed.

## Not re-verified on Linux
The fix was verified on Windows only, by a CRLF/LF unit test. The Linux VM was torn down before the fix existed, so the corrected pins have not been re-run there.
